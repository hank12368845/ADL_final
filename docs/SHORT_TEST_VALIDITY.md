# 短測有效性檢查（2026-11-18）

結論：現有 3×3 單場短測能定位真實操作錯誤，不能可靠估計正式得分，
也不能隔離單個 persona 修改的收益效果。不要把同場平均增加或個別下降當成版本選型結論。

## 已從程式與實際結果核對

- 沒有砍回合：5 rounds×6 turns，每位 agent 30 actions。
- 使用原始 Market／Runner／tools／score_market；外部 wrapper 只準備資源、衍生設定、顯示進度與分析。
- 一般 v1／v2 的初始 products、sellers、buyers 逐欄相同，公開24項商品、各 buyer 514.24、seed 0。
- engine 用 `random.Random(market:seed:seed_id)` 配置與套用順序；政策將同一 seed 傳給模型，client 確實送出 seed。
  不能說這些測試沒有控制 seed。相同配置重跑的服務端重現性與分數變異尚未實測。
- temperature 0.7、top_p 0.95，實際 prompt 中三份 persona 與被測版本相符。
- 原始 engine 先收集同一 tick 的私人 observation，再並行生成決策，最後依 RNG 順序套用；
  看到一件庫存仍可能因其他 buyer 先成交而失敗。不能把所有 no_stock 都當未看庫存。
- low 測試換了 seller 身分與控制器。該 scripted probe 的低品質確實有交付，
  但與一般測試的總分差混有價格／供給時機／對手行為差異，不等於品質單一效果。

## 比較上的主要限制

1. 同時修改三個 persona，並在同一個市場競爭。某 persona 的得分變動包含其他兩個的策略變動，
   改版前後相同 seat／seed 也不能消除這種干擾。
2. 每份只有一場；三個不同 persona 不是同一 persona 的三次獨立重複。
   Owner 列 markets=3 和 se 也不能當作某 persona 的三次實驗與可信區間。
3. 3 sellers×3 buyers 不等於正式5×10。市場供給按人數取整、集中商品分配及搶貨競爭均改變。
   無 seller 庫存輪換、只有公開商品與少數 toy TA，缺乏正式泛化證據。
4. 分數是互動結果。某版本實際少賺是該場事實，但不等於已證明該 persona 整體退步。
   目前不能認定 p1 v1 是可靠較強版本，只能說它在已觀察的一場得到較高分，應保留作候選。
5. 讀取狀態也需符合本地引擎：先low後high可能帶來正的升級邊際效用。
   數量超出一件是當前 persona 的保守限制，不能一律稱作引擎扣分或零效用。

## 哪些結論仍有直接證據

- 已持有 high 後又買 high，交易 utility=0 卻扣款，確實減少 surplus。
- 對當前沒有掛牌的 seller/product 使用 buy_listed，且引擎回 not_listed，確實浪費一次行動。
- 記憶為普通句子而非要求的 JSON、held/cash 自檢沒有輸出，確實沒有遵從這項指示；
  不等於已證明只要改 JSON 就會提高收益，或是所有錯誤均由記憶格式造成。
- 實際 quality_varies=true，筆記卻稱 fixed quality；已收到 low 的下一回合仍依高品質完整值購買同 seller
  的另一項 variable 商品，是具體的風險判斷錯誤。
- 初次收到隱藏 low 本身不必然代表錯誤；應檢查購買前可用資訊和預期收益。

## 建議的省時驗證順序（尚未建立／執行新的 GPU 評估）

1. 固定觀測的決策測試：挑出已持有high、沒有掛牌、已知low證據、無交易須wait、有效counteroffer等案例。
   各版本取得相同市場狀態／歷史／工具，檢查有效動作集合及state真實性；不要要求唯一交易答案。
   這能低成本隔離讀狀態／工具遵從，不評估整場收益。
2. 受控版本比較：每場只替換一個被測 persona，其餘 buyer 與 seller 版本固定；
   對應seed、角色ID、席位、商品與服務設定固定，先用少數配對seed篩選。
   固定其他LLM政策仍會產生互動反應；可另加規則對手提高可解釋性，但不能當正式強度。
3. 品質對抗：用同一probe ID／價格規則的high與low設定配對，記錄可見證據、後續購買、
   負收益與放棄好交易的機會成本。需要多場才能估計穩定差異。
4. 候選通過診斷後，用正式5×10的一個市場完整30turns測試，先不用整套3economies×5rotations。
   接著才增加市場、對手、商品與輪換。

這比「等小市場看起來穩拿高分才長測」更合理：小市場無法先保證正式高分。
目前不應因本次檢查就重跑所有舊短測或繼續只根據單場得分改 persona。
